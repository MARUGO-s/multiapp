# kotonoha — 録音の端末内保全と通信復旧後の再送

## 調査で確認した既存の問題

調査対象は `origin/main` の `5198157`（最新ソースから隔離した `fix/kotonoha-offline-recording`）。元の利用者作業ツリーは変更しない。

- `src/recording.ts` は録音中のチャンクをIndexedDBへ保存するが、停止時と復元時にファイルを返す前に録音セッションを削除する。この時点ではサーバーへの保存はまだ行われていない。
- `src/NewMeeting.tsx` のファイル・会議名等はReactのメモリー上の状態で、送信前の録音を永続的な取り込み待ちとして管理していない。録音中の画面離脱の後処理は `cancel()` を呼び、チャンクを削除する。
- チャンク保存エラーは握りつぶされ、保存失敗を利用者へ伝える経路がない。
- `src/upload-recordings.ts` の送信は新規作成・音声部分・添付資料・完了の順だが、再開用の識別子と処理状態を端末に永続保存しない。
- `kotonoha-api/handler.ts` の従来の `POST /uploads` は要求ごとに新しいIDを生成する。既存の音声部分APIは先頭から順番の追記であり、応答が失われた後に単純に同じPOSTを送り直すだけでは安全な再開を保証できない。

以上はソースで確認した消失・再試行リスクであり、今回消えた録音の実機ログや実際の消失時点を特定したものではない。停止・復元後に既存コードが削除済みの録音を、今回の改修だけで復旧できるとは保証しない。

## 必要な動作

1. 録音中は端末内へ継続保存し、停止・復元・通信失敗だけでは消さない。ストレージ保存不可・容量不足を正常な保存として扱わない。
2. 会議名・開催日・参加者等の入力、送信用音声と添付資料を端末内の下書きとして保持し、再読み込み・フォームの再表示後に復元できるようにする。
3. 利用者が送信を依頼した下書きだけを送信待ちにする。まだ編集中の入力を勝手にサーバーへ送信しない。
4. オフライン、オンライン表示のままの通信切断、応答喪失、タイムアウト、一時的なサーバーエラーでも音声と送信内容を残す。
5. 回線復帰、アプリの前面復帰、適切な待機を挟んだ再試行と明示的な再送で再開する。接続状態フラグだけを成功判定に使わない。
6. 同じ操作の再開は同じ識別子と固定した内容で行い、作成・部分送信・完了の応答が失われても二重登録しない。連打・複数タブにも対応する。
7. 認証切れ・権限不足・入力不正は回線エラーと区別し、無限再送しない。再ログインでローカル音声を消さず、誤った利用者・保存先へ自動送信しない。
8. 送信待ちの表示、手動再送、端末への音声ダウンロードを用意する。ユーザーの追加依頼により、全音声・添付資料・会議情報がサーバーへ保存されたことを正しい識別子と保存結果で確認できた時点で、その送信に属する下書き・準備済み部分・録音原本・録音セッションを自動削除する。AIによる文字起こし・議事録生成の完了を待つものではない。送信失敗・一部だけ保存・応答不明の間は削除しない。別の未送信録音や編集中下書きは削除しない。サーバー保存後の端末側削除に失敗しても、次回は削除処理のみ再実行し、会議を新規登録し直さない。利用者が明示的に破棄した場合も、その対象だけを削除する。
9. 既存の配色、入力検証、認証、音声分割・添付形式・容量制限を維持する。Botや有料AI処理を不確定な通信結果から無条件に再実行しない。

## 録音開始位置の追加要件

ユーザーは位置情報の追加も承認し、共有範囲を「会議を閲覧できる人に共有し、後から削除可能。PDF・書き出しには自動で載せない」と指定した。

- 「録音場所を記録する」は任意とし、ブラウザーの位置情報許可を得た場合のみ録音開始地点を取得する。常時追跡しない。
- 録音の開始に結び付けた緯度経度・取得精度・取得時刻を保存する。音声ファイル本体へのGPS埋め込みは不要。
- 許可拒否、取得不可、位置取得のタイムアウトで録音を失敗させない。遅れて届いた位置情報を、停止済みの録音・別録音・別下書きへ誤って結び付けない。
- オフラインでは取得できた座標を録音と同じ端末に保持し、送信待ちの音声・会議情報と一緒に同期する。取得できない場合に現在地を推測・捏造しない。
- 会議の詳細から取得場所と地図へのリンクを確認できる。座標を第三者の地図サービスへ送る場合は、利用者の明示的な操作が必要。自動で外部逆ジオコーディングを実行しない。
- 位置情報は認証済みの会議閲覧範囲で共有し、会議画面から削除できる。削除済みの場所が後の再生成や再送で復活しないようにする。
- 印刷/PDF、Markdown、文字起こしTXT、JSON、ICS、一括書き出しには録音位置を自動で含めない。AIへの入力・利用料金ログ・公開QRには送らない。
- 屋内・省電力設定・端末やOSの測位能力によって精度や取得可否が変わる。住所・建物名・店舗名を常に特定できるとは保証しない。

## 保証範囲と制限

- 対象は現在のkotonoha Webクライアントと、取り込み再開に必要な最小限の既存API・永続化経路。ほかのアプリのデータ・権限を変更しない。
- スマートフォンでアプリを閉じている間の録音・送信継続は保証しない。再開はアプリを開いて操作できる状態が前提。
- 初めて開くページをネットなしで起動できること、認証切れでもログイン不要で利用できることは別の要件であり、本機能の保証に含めない。
- 端末内保存は同じ端末・ブラウザー・サイトの保存領域に属する。ブラウザーのサイトデータ削除、プライベートモード、OSによる保存領域の消去、端末破損に対する絶対保証はできない。重要な録音はダウンロードで別途保全する。
- ユーザー承認前の本番公開・業務データ操作・有料AI呼び出しは行わない。
