# kotonoha — 会議録ワークスペース

録音済みの音声を取り込み、文字起こし → 会話解析 → 議事録作成まで一括で行う日本語Webアプリです。ブラウザーでその場で録音することもできます。

公開先: [kotonoha](https://marugo-s.github.io/multiapp/)

## アプリの入口

multiappのトップページには、hibinowa（LINEレポート）・ajisai（レシピ管理）・meguri（貸借管理）・musubi（M-talk）・shiori（Journal Report）・mimiyori（口コミ・グルメサイト管理）・Instatic TalksX（SNS一括管理）へ移動する7つのリンクボタンがあります。SNSの移動先は [Instatic TalksX](https://marugo-s.github.io/sns_management/) です。機能名はサブタイトルに表示し、名前は入口での表示だけを変更します。各アプリのURL・アプリ内の名称は変更しません。ログイン前でも開けます。同じタブで各アプリへ移動し、ブラウザーの「戻る」で入口へ戻れます。移動先のログイン・アクセス権は各アプリの設定に従い、multiappのID・パスワードやセッションをURLに付けて渡しません。

入口は「アプリを選択 → 共通ID・パスワード → ログインして開く」の順です。kotonohaとMARUGO QRは同じID・パスワードを使います。スマートフォンではログイン欄を先に表示します。Google・QRの個別メールログインや新規登録・再設定は「別の方法でログイン」にまとめています。追加のリンクボタンは移動先の認証設定を変更しません。

## QRコード作成・アクセス計測

お披露目期間はMARUGO QRを選び、kotonohaと同じ共通ID・パスワードでログインします。全店舗（旧QRを含む）のQR・アクセス履歴・ファイル・ゴミ箱と、QRのアカウント管理を利用できます。共通IDの操作は個人特定できません。運用開始時には下記の共通利用スイッチを無効にして、個別アカウントへ切り替えます。

個別メールログインも「別の方法でログイン」から利用できます。新規登録時に所属店舗をプルダウンで選択し、メール確認と管理者承認後にその店舗を管理します。パスワード再設定はメールの本人確認リンクで行います。会議メニューを持たない独立した画面です。管理用の名前とリンク先のHTTP/HTTPS URLを登録します。OpenAIのAPIキーは不要です。

共通IDで入った場合はkotonohaとQRで同じセッションを使い、どちらでログアウトしても共通ログインが終了します。個別メールの一般メンバーは所属店舗だけを管理できます。全店舗管理者は店舗を切り替え、登録ID・メール・所属・承認状態と管理者権限を管理できます。既存QRはコード・履歴を変えず「未割当（旧QR）」に保持します。詳しい手順は [店舗別アカウント](docs/qr-store-accounts.md) を参照してください。

共通QR利用の停止（対象 `hjhkccbktkscwtgzxjfq` の管理者SQL）:

```sql
update kotonoha.access_config set qr_shared_login_enabled=false where singleton;
```

停止後は既存の共通セッションも次のQR要求から拒否します。kotonoha・個別QRアカウント・公開QRは引き続き使えます。Google連携で発行した会議録セッションは共通QR権限に使いません。

QRに入る短縮URLは `https://marugo-s.github.io/multiapp/?s=q#AbCd1234EfGh` の形です。ホスト名にmarugoが入っているため追加のパスは省略しています。識別コード付きの入口は管理画面やログイン処理を読み込まず、`marugo-qr/scan` にアクセスを記録し、成功後にリンク先へ自動転送します。同じ公開パス内のマーカーなしURL `/multiapp/#コード` と `/multiapp/marugo/#コード` にも対応します。リポジトリ名変更前の `/OEM/` はGitHub Pagesの自動転送対象外のため、既存の登録リンクを開き、新しいURLのQRを再保存・配布してください。データベースと履歴は変更しません。JavaScriptとネット接続が必要です。URLの直接クリック・同じ方の再読み込み・ボットも1回として数え、カメラで認識しただけの回数や移動先の表示完了・人数は計測しません。

登録済みリンクを選ぶとQR画像の再表示・PNG保存・短縮URLコピー、回数とアクセス履歴（日本時間、経路・流入元ドメイン・端末・ブラウザー）を確認できます。回数・履歴・分析は表示中に約10秒ごとに更新します。「転送を停止」で公開リンクを停止でき、「転送を再開」で同じQRを再利用できます。

### QRのゴミ箱・復元・完全削除

登録済みQRを選び「ゴミ箱へ移動」を押すと、確認後に通常一覧から外し、QR・短縮URLの転送を停止します。設定・アクセス数・全履歴は残ります。「ゴミ箱」の一覧は権限のある店舗内だけで参照でき、約10秒ごとに更新します。ゴミ箱から「復元」で同じコード・履歴を戻せますが、転送は停止中です。必要に応じて通常一覧から「転送を再開」してください。

完全削除はゴミ箱内のQRだけに実行できます。確認画面で「QRコードと全アクセス履歴が消え、復元できない」ことをチェックしてから「完全削除する」を押します。QR設定と全アクセス履歴を1つのトランザクションで削除し、元には戻せません。削除済みのQR・短縮URLは使えなくなります。ゴミ箱の自動削除・一括削除はありません。停止・復元・削除とアクセス計測は同じ行ロックで順序を制御します。

### QR・リンクボタンと多角的なアクセス分析

- QR画像は `?s=q#コード`、リンクボタン用URLは `?s=b#コード`、通常リンク用は `?s=l#コード` を使用します。どれも同じ登録リンクへ転送され、追加の `/marugo/` パスはありません。用途ごとのURLをコピーしてサイトのリンク先に指定できます。「リンクボタンのHTMLをコピー」は、そのままHTMLへ貼れるリンクボタンを生成します。
- 同じURLだけではQRを撮ったかボタンをクリックしたか判別できません。経路はURLの識別マーカーに基づく分類です。QR用URLをボタンに使えばQR経由として数えられます。同じ公開パス内のマーカーなしURLは利用を継続でき、経路は「不明・旧URL」になります。既存の履歴は保持し、当時取得していない経路情報は補完しません。
- 「アクセス分析」で直近7日・30日・90日（今日を含む、日本時間）の折れ線グラフ／日別表を切り替えます。0回の日も表示し、グラフの点を選ぶと正確な回数が分かります。累計・選択期間・今日の回数も表示します。
- 主指標は延べアクセスの累計・選択期間・今日の3つです。人数・スマホの台数は計測しません。「ブラウザー単位の参考値を見る」を開くと、同一QR内の匿名IDを期間内に1件として数えた参考値の累計・期間・今日と、グラフ切替・日別表／各内訳の参考値を表示します。閉じると延べアクセスのグラフへ戻ります。同じスマホでもコードスキャナーやアプリ内ブラウザーでIDが引き継がれないと別件になり、実人数や来店人数としては使えません。IDはQRごとに別々にlocalStorageへ最大180日保存し、サーバー側でQRコードと合わせてSHA-256に変換します。生ID・IP・Auth IDはDBに保存しません。別ブラウザー・シークレットモード・保存データ削除・期限切れでも別件となります。旧履歴や保存不可は「匿名ID未取得」、推定ボットは別表示し、どちらも延べアクセスには含み参考値には含めません。アクセスがあって参考値がない場合は「未計測・対象外」と表示し、グラフは欠測として線を切ります。アクセス自体がない0件と区別し、過去の参考値を推測で補完しません。ID取得済み・未取得が混在する参考値は取得済み分のみで、日別・分類別の参考値の合計は期間全体とは一致しません。詳細・反映手順は [ブラウザー参考値](docs/qr-unique-analytics.md) を参照してください。
- 流入経路を絞り込み、経路別・端末別・ブラウザー別・流入元サイト別のグラフ／表を確認できます。流入元は上位10ドメインとそれ以降をまとめた「その他」を表示します。集計は保存済み全履歴の対象期間からDB側で行い、履歴一覧30件のページ数には依存しません。
- 流入元はブラウザーが渡す `document.referrer` のドメインだけを保存します。IP、流入元のパス／クエリー、位置情報、Cookieによる個人識別は保存しません。プライバシー設定・アプリ内ブラウザー・直接アクセスでは流入元は不明となる場合があります。端末・ブラウザー・ボット等はUser-Agentによる推定です。人数・購入・移動先の表示完了は計測しません。
- 取得失敗時は「0回」に置き換えず、前回の集計と取得日時・エラーを示します。分析結果の参照は認証と店舗権限のある管理画面内に限定し、匿名の計測ページへ履歴を返しません。

専用の `kotonoha.qr_links` / `kotonoha.qr_access_logs` に保存し、公開RPC `kotonoha_qr` はService Roleだけが実行できます。管理APIはSupabase AuthのJWTを検証し、QR専用の所属・利用状態・管理者権限をDBで確認します。旧共有セッションではQR管理できません。匿名の公開APIはランダムコードのアクセス記録のみで、履歴一覧を公開しません。履歴追加とカウント加算は同一トランザクションで、同じイベントIDの通信再試行は二重計上しません。リンク作成も同じリクエストIDでの再試行に対応します。ページを改めて開いた場合は新しいアクセスになります。

QR用マイグレーションだけを適用し、`marugo-accounts` と `marugo-qr` の専用関数を公開します（各関数で独自のAuth本人確認を実装、店舗一覧と計測/公開閲覧は匿名ルート）。会議録APIや他アプリの権限は変更しません。QRの作成・計測はクラウド専用です。ローカル確認は `VITE_STORAGE_MODE=supabase` と個人のメールログインを使います。メール送信・戻り先の本番設定は専用ドキュメントに従って既存設定を残したまま確認します。

## 使い始める

1. 共通ID `marugo` と管理者から受け取ったパスワードでログインします。全員が同じ会議・音声・議事録を閲覧・編集します。既存Supabaseアカウントは使いません。
2. 左メニュー「接続設定」に、ワークスペース共通のOpenAI APIキーを入力します。文字起こしは `gpt-transcribe` または `gemini-3.5-transcribe` から選択でき、Geminiを選ぶ場合はGemini APIキーも入力します。議事録は `gpt-6-astra`・`gpt-6-sol`・`gpt-6-luna` から選びます。対象モデルの権限・利用枠が必要です。設定保存は疎通確認を意味しません。
3. 録音ファイル、その場での録音、または文字起こし済みのトークを取り込みます。途切れて複数ファイルになった録音は、まとめて選び、上下ボタンで録音順に並べてください。ファイルの追加・解除もできます。会議名、開催日、参加者、議事録の詳しさを指定できます。
   - 「その場で録音」では、ブラウザーのマイクで直接録音できます。会議を**ブラウザーのタブ**で開いている場合（Google Meet、ブラウザー版Zoom/Teamsなど）は、PCのChrome/Edgeで「マイク＋会議の音声」を選び、共有ダイアログで「Chromeタブ」→会議のタブ→「タブの音声を共有」を選ぶと、相手の声も録音できます。**ZoomやTeamsの専用デスクトップアプリ**で参加している場合や、Safari・Firefox・スマートフォンでは、この方法で相手の声を拾うことはできず、マイクのみの録音になります。
   - 録音中は数秒ごとに端末内（IndexedDB）へ保存するため、誤ってタブを閉じても直近の数秒分以外は次回開いたときに復元できます。録音はアプリを開いたまま行ってください（バックグラウンドでの継続録音はしません）。
4. 「議事録」「文字起こし」「アクション」で確認・編集します。議事録は要約版／標準版／詳細版（背景も詳しく）を1回のAI応答でまとめて作成し、タブで切り替えます。切り替え時のAI呼び出し・課金はありません。編集・コピー・Markdown／印刷・PDF出力は選択中の形式が対象です。JSONには全形式を含みます。以前の単一形式はそのまま表示し、「3形式を作成」から明示的に再生成できます（AI使用料がかかります）。保存済み文字起こしは再利用し、未完了の音声のみ文字起こしを行います。再生成すると3形式すべての編集済み本文と完了チェックを上書きします。既存タグと予定の手動変更は保持します。キャンセル時は変更しません。
5. Markdown・テキスト・JSONで書き出せます。印刷画面からPDFにも保存できます。

### 議事録の基本形式

| 形式 | 内容 |
| --- | --- |
| 要約版 | 主な方針・決定事項と次の対応を短く整理 |
| 標準版 | 議題ごとの結論に、必要な背景・経緯を添えて整理 |
| 詳細版（背景も詳しく） | 背景・理由・異論・検討の経緯まで会話の範囲で整理 |

3形式とも「基本情報 → 内容要旨 → 決定事項 → 議題別の内容 → 次の対応（担当・期限の表） → 継続検討・確認事項 → 次回会議」を基盤にします。これは固定の穴埋めではなく、会議内容に合わせて議題を統合・分割し、該当しない項目は省略します。次回会議は明確な言及がある場合だけ記載し、翌日の訪問などとは区別します。サンプルの1／3／5ページに固定せず、長い会議は必要な分量を確保し、短い会議は水増ししません。

要約版でも重要な作業・担当・期限は省略しません。決定・方針・提案・調整中を区別し、不明な担当・期限は未定、相対日付は原文を維持します。決定事項・アクション・継続確認事項・予定は共通で1組だけ生成し、内容要旨と議題の説明を3段階に書き分けます。初期表示は従来どおり詳細版で、作成時に選ぶ形式は「最初に表示する形式」です。形式の選択だけで会議名・参加者は変更しません。保存済みの議事録や手書き本文を自動で書き換えることはありません。

形式の定義は `supabase/functions/_shared/minutes-formats.mjs`、生成指示・3形式の構造化応答は `summary.mjs`、本文の構成は `domain.mjs` で共有しています。旧形式ID `brief`／`standard`／`detailed` は維持します。`minutes.formats` に3形式の要旨・議題、`markdownByFormat` に各本文を保存し、旧クライアント用の `minutes.summary/topics`・`markdown` は初期表示形式を指します。本文のPATCHは `markdown` と任意の `markdownFormat` で1形式ずつ保存し、他形式やAI抽出値は変更しません。旧応答・デプロイ時に実行中の単一形式も引き続き読み取れます。3形式の一部が欠けた応答は成功扱いにせず、再生成失敗時は既存本文を保持します。生成上限は内部推論を含む24,000トークンで、料金は実際の使用量を従来どおり1件の議事録生成として記録します。1形式と同額を保証するものではありません。

表示の検証は `node scripts/check-minutes-ui.mjs` で行えます（`http://127.0.0.1:5198/`、APIは5197番）。一時保存先の架空データとダミーAIのみを使い、本番の会議・保存済みのキー・有料AIは使いません。3形式を持つ架空会議3件と旧単一形式1件で、タブ・編集・旧データ互換・表の表示を確認します。実AIの詳しさ・品質評価ではありません。

左メニューの「API使用料」では、対象月のドル円レートを入力・保存すると、解析1回ごとの概算料金と月合計を円で確認できます。レートはそのブラウザーに月ごとに保存され、請求時の実際の為替を自動取得するものではありません。解析の内訳を開くと、API呼び出しごとの日時、モデル、入力・出力トークン、音声時間、料金を確認できます。録音を分割した場合は同じ解析にまとめ、議事録の再生成は別の解析として表示します。解析IDを記録する前の旧履歴は会議と処理順から推定してまとめます。会議を削除しても利用履歴は残ります。記録開始以前の利用は遡及できません。

料金は実行時の単価で保存します。GPT Transcribeは1分$0.0045、Gemini 3.5 Transcribeは入力100万トークン$2・出力$12、GPT-6 Astraは入力$10・出力$50、GPT-6 Solは入力$2・出力$10、GPT-6 Lunaは入力$0.10・出力$0.50（2026-09-24の標準料金）。応答に使用量がない音声は録音時間を使った推定として表示し、時間も不明なら料金は算出不可とします。無料枠、税、為替、APIプロバイダー側の調整は反映されません。請求額は[OpenAI](https://developers.openai.com/api/docs/pricing)と[Google](https://ai.google.dev/gemini-api/docs/pricing)の請求画面で確認してください。

ログイン後の「サンプルを開く」はOpenAIキー不要です。架空の固定データであり、AI処理をしたふりはしません。

## 会議の添付資料

- 添付資料は会議の参考資料として保存・共有するだけです。AIには送信せず、文字起こし・議事録の解析にも使いません。資料の追加・解除で議事録は未反映になりません。
- 新しい会議の「会議の添付資料」で、資料をドラッグ＆ドロップするかボタンから選択します。録音・会話テキストと一緒に選び、音声・全資料の保存が完了してから会話を解析します。資料だけでは会議を作成できません。
- 既存の会議にも「添付資料」タブへドラッグ＆ドロップまたはボタンで追加して保存できます。ほかのタブを表示中に会議画面へドロップしても「添付資料」タブに切り替わります。解析中は資料を変更できません。
- 対応: PDF、Excel（XLSX / XLS）、Word（DOCX / DOC）、PowerPoint（PPTX / PPT）、CSV、TXT。最大5ファイル、各10 MB、合計25 MB。録音の100 MBとは別枠です。パスワード保護は解除してください。
- 新規取り込み時は資料の内容をSHA-256で照合し、ファイル名のUnicode表記差に左右されず選択時の名前で保存します。内容やサイズが違うファイルへのすり替わりは拒否します。
- 元のファイルは専用の非公開 `kotonoha-documents` バケットに保存し、全員で共有します。ログイン後にダウンロード可能です（署名付きURLは10分有効、外部共有しないでください）。ブラウザー内でマクロ・添付ファイルのコードを実行しません。
- 以前の版で資料と照合した議事録の「添付資料との照合」は、再生成するまでそのまま表示します。
- 資料の「関連付けを解除」は資料一覧から外す操作です。保存ファイルと旧メタデータは保持します。会議自体を削除しても資料は保持し、復元・完全消去は管理者対応です。ローカルでは資料を `.data/attachments/` に保存し、会議削除時は解除済み資料も `.data/trash/<ID>/` に移動します。

## 共有カレンダーと手動編集

- 「カレンダー」で月間表示と予定一覧を切り替え、日付を選ぶと時間・場所・担当・元の会議・根拠を確認できます。検索、予定／期限、確定／予定案／要確認の絞り込みに対応します。サンプル会議は含めません。
- 予定カードの「削除」で1件、画面上部の「選択して一括削除」で複数件をカレンダーから除外できます。確認画面で対象を確認して実行し、下部の「削除済みの予定」から復元できます。元の会議録・文字起こし・資料は消しません。同じ予定の非表示は再生成後も保持しますが、AIが別内容として抽出した予定は新しい候補として現れる場合があります。
- 新しい解析では `minutes.scheduleEvents` に予定を構造化して保存します。時刻は日本時間、期間の終了日は含みます。会議日を基準に明日などを解決し、曖昧な「来週まで」「月末」や日付不明は日付要確認欄に置きます。資料にしかない予定は確定にしません。判定もAI出力なので原文と照合してください。
- 以前の議事録は再解析なしで決定事項・期限から候補を表示します。年のない日付は会議年の候補とし、全件要確認です。旧形式の相対日付・複数の日付は自動確定しません。
- 「予定を編集」から予定名・日付・時間・場所・担当・状態を変更できます。全員に共有され、OpenAIを呼びません。元の根拠は保持し、専用JSONの `calendarOverrides` に予定ごとに原子的に保存します（1会議最大200件）。再生成後も変更を保持し、元の予定が変わった場合は要確認にします。確認・保存で状態を更新でき、「元の抽出結果に戻す」でその手動変更だけ解除します。
- 議事録タブの「議事録を編集」で本文を修正して「保存」すると全員に反映します。本文とカレンダー、AI抽出の要点・決定事項・アクションは別管理です。本文を書き換えても他の欄は自動更新しません。再生成は編集済み本文と完了チェックを上書きしますが、予定の手動変更は保持します。
- 会議名は詳細画面の「名前を変更」、または左メニュー「最近の会議」の鉛筆ボタンから変更できます。一覧・詳細・API使用料の会議名・書き出し名に反映し、議事録本文の先頭が旧会議名の見出しならその見出しだけ更新します。旧会議名と一致しない見出しや本文は変更しません。
- 同じ予定・本文を同時編集した場合は最後の保存が優先です。別の予定の更新は相互に上書きしません。解析中の予定編集はできません。外部カレンダーへの自動同期はありません。

## 集計・タグ・比較・通知

- API使用料は、文字起こし・議事録生成・タグ候補生成（再取得分を含む）を同じ解析ブロックに合算します。議事録の再生成は別ブロックです。既存の独立したタグ履歴は、同じ会議の直前の議事録生成に紐付けて「タグの紐付けは推定」と表示します。元の料金履歴と月合計は変更しません。月をまたぐ処理は各月に分かれます。

- 「統計」のAIサマリーは「今月」「先月」「直近7日」「期間指定」から選べます。先月は日本時間の前月1日〜末日、期間指定は開始日・終了日を含みます。終了日は日本時間の今日までです。対象期間に開催した解析完了の会議だけをまとめ、サンプル・未来の会議・未完了の解析は含みません。編集済み議事録とアクションの完了状態を送信し、見出し・会議ごとの小見出し・段落・箇条書き・太字で表示します。結果は画面内だけに表示し、期間が広く入力上限を超える場合は短い期間で再実行してください。
- アプリを開いている間に議事録が完成すると、AIタグ候補を自動生成してポップアップに表示します。複数件は順番に表示し、選んだ候補を「選んだタグを保存」で会議に紐付けます。選択だけ・閉じるだけでは保存しません。既存タグは残ります。候補生成が失敗しても議事録は利用でき、再取得は手動です。過去の完了会議や画面を閉じている間に完了した会議には、詳細の「タグ候補を開く」を使ってください。同じ画面内では候補を再利用しますが、再読み込み後は再生成になります。会議に付けたタグは全員に共有され、同時編集は最後の保存が優先です。手動で作った未使用のタグ名だけはブラウザー内の保存です。
- AIサマリーとタグ提案は、接続設定で選んだ議事録モデルとOpenAIキーを使用します。「API使用料」に種類・使用量・概算料金を記録します。通信が切れた場合、料金や結果を取得できないことがあります。二重実行を避けるため自動再送はしません。
- 「会議比較」では2〜5件を選択できます。2件選択した後も追加・解除できます。
- 時間比較・総録音時間は分割音声の時間を合計します。時間が不明な会議は「未取得」とし、平均・合計から除外します。既存の会議も再解析せず反映されます。
- 会議ライブラリの各会議にも、日付・参加者と並べて録音時間を表示します。
- 一括Markdown書き出しは保存済みの議事録本文を含みます。ICS書き出しは選んだ会議の開催日を終日予定として出力します。会話から抽出した個々の予定を同期する機能ではありません。
- 接続設定からブラウザー通知を許可すると、アプリを開いている間、カレンダーの確定済み・期限超過の項目を通知します。同じ期限は同じタブで1回だけ通知します。アクションと内容・担当者が一致する完了済み項目は除きます。アプリを閉じている間の通知や、すべての端末での通知は保証されません。
- 音声の変換・必要な再圧縮は取り込み時に行います。保存済み音声を後から最適化する機能はありません。

## データと安全性

- Supabaseプロジェクト `hjhkccbktkscwtgzxjfq`（Recipe-Management）に間借りしています。会議録専用の非公開 `kotonoha` スキーマを使い、既存の業務テーブル・関数・Storageポリシー・Auth設定を変更しません。
- 会議・音声・設定・追加・編集・削除は全員共通です。他の人の変更は約10秒ごとに一覧へ反映します（本文編集中を除く）。同じ内容を同時に編集した場合は最後の保存が優先されます。
- 共通パスワードはbcryptハッシュとして専用DBに保存し、公開コードには含めません。認証成功時にランダムな12時間のセッションを発行し、DBにはそのSHA-256ハッシュのみ保存します。ログアウトはそのセッションを失効させます。失敗が続くと15分のログイン制限がかかります。
- ブラウザからテーブルや保存RPCを直接呼べません。`kotonoha-api` が専用セッションを検証してから、全員共通のワークスペースを操作します。共用Supabase Authにはユーザー追加や設定変更を行いません。
- 音声は非公開バケット `kotonoha-audio` に保存し、ログイン済み利用者に1時間の署名付き再生URLを発行します。URLは外部へ共有しないでください。
- OpenAIキーとGeminiキーはワークスペース共通で別々にAES-256-GCM暗号化し、会議録専用のサーバー鍵で保存します。他アプリのAPIキーは使用・変更しません。旧個人キーは共通キーへ自動転用しません。
- GPT-4o文字起こしでは音声をOpenAIへ送信します。Gemini文字起こしでは音声をGoogleのGemini Files APIへ一時送信し、文字起こし後に一時ファイルの削除を要求します。テキスト・議事録生成はOpenAIへ送信します。添付資料はAIへ送信しません。議事録はResponses APIのStructured Outputs（medium）を使用。クラウド版は長い生成に対応するため `background: true, store: true` です。結果取得に必要なデータがOpenAI側にも保存されます。機密情報の利用可否を確認してください。
- 削除は論理削除で、通常画面から非表示になります。音声は保持します。復元・完全消去は管理者対応で、自動消去はありません。
- 「新しい会議」の「Botを呼ぶ」でGoogle MeetのURLを入力すると、録音専用のBotに参加を依頼できます（クラウド版のみ）。Botにはパスワードを渡さず、その会議だけに使える6時間有効のアップロードトークンを渡します。状況（待機中／参加中／録音中／アップロード中／議事録作成中／完了／エラー）は会議の画面に表示されます。設定は [DEPLOYMENT.md](DEPLOYMENT.md) を参照してください。
- 画面を閉じた後の処理は、Supabaseの定期実行（pg_cron、毎分）が内部API `POST /internal/tick` を呼んで進めます。内部APIは専用の合言葉（Vaultと関数の環境変数に保存）でのみ実行でき、利用者のログインでは呼べません。会議内容は返さず、処理の排他制御と同時AI処理2件の上限は画面からの処理と共通です。初回設定は [DEPLOYMENT.md](DEPLOYMENT.md) を参照してください。
- Supabaseの計算資源は共用なので、負荷や利用枠まで完全に分離するものではありません。同時AI処理は共有ワークスペース全体で2件です。
- 共通ログイン情報を知っている人は全記録と設定を操作できます。利用者ごとの権限・監査ログはありません。共用端末では利用後にログアウトしてください。

## 対応範囲と制限

- 音声: AAC / MP3 / M4A / WAV / MPEG / MPGA / OGG / FLAC。動画: MP4 / M4V / MOV / MKV / WebM / MTS / M2TS / TS / 3GP（音声トラックだけを使い、映像は送信しません。映像コーデックは問いません）。1会議は最大5ファイル・合計100 MB（100,000,000バイト）まで。単一100 MB・異なる形式の混在にも対応します。
- ブラウザー内のWorkerでMediabunnyを使い、最大約10分または音声データ20 MBごとにパケット境界で分割します。AAC・MP3・Opus・Vorbis・FLAC・リトルエンディアンPCMはPCMへ全展開せず、再圧縮せず、各部分に再生可能なヘッダーを付けます。AAC（ADTS、AAC入りMP4/MOV/TS）はM4Aに変換。破損AAC・途中で形式が変わるAAC・ADIF/LATMなど非対応形式はエラーにします。
- そのままでは文字起こしAPIへ渡せない音声（動画に多いDolby AC-3 / E-AC-3、カメラのMOVに多いビッグエンディアンPCMなど）は、ブラウザー内でデコードして16 kHzモノラルの音声に再圧縮し、同じ長さの部分（各10分以内）に分割します。Opusで書き出せるブラウザーはOgg Opus（約32 kbps）、次にAAC、どちらも使えない場合は16-bit WAVです。AC-3 / E-AC-3のデコーダー（`@mediabunny/ac3`、約1.1 MB）は該当ファイルを選んだときだけ読み込みます。DTS・AMR・ALAC・WMAなどデコードできない音声、AVI・WMV・FLVなど読み取れない形式はエラーにします。その場合は動画をAAC音声のMP4、または音声をM4A・MP3・WAVで書き出してください。
- 複数録音は各文字起こしに「録音1」「録音2」…の区切りを付け、指定順で連結して1つの議事録にまとめます。音声ファイルそのものを1本に結合する機能ではありません。録音間の欠落・重複は推測で補完／削除しません。文字起こしタブで録音を切り替えて再生できます。
- 分割音声を順番に送信し、すべて保存できた時点で文字起こしを開始します。各リクエストと専用Storageの上限は24 MBのままです。原本合計100 MB、変換後合計110 MB、分割数512、取り込み途中の会議2件までをサーバーでも検証します。送信中は画面を開いたままにしてください。中断した取り込みは一覧で削除し、ファイルを選び直せます（未完了の音声は削除、通常の会議は従来どおり論理削除）。
- 新規アップロードはクラウドで1回の処理につき1部分を文字起こしし、保存後に次の処理権をDBで排他的に取得します。複数端末の同時閲覧で二重実行しません。完了済みは再処理せず、未完了だけを再試行。直前の文字起こし末尾を次の認識の文脈として渡します。すべて揃ってから議事録を生成。旧24 MBの一括API・既存の会議も互換維持しています。
- クラウドの文字起こし待機上限は1部分110秒。分割境界は無音検出ではなくパケット境界です。原本に重複があっても自動削除しません。長時間の文字起こしも合計10万文字までで、それを超える場合は会議を分けてください。
- トーク貼り付けは10万文字まで。共有ワークスペース全体で最大1,000会議。
- 文字起こし結果に、アプリ側で話者名・発言時刻を推測して付けません。サンプルの話者と時刻は説明用の固定データです。
- AIには決定と提案を区別し、明示されていない担当・期限を「未定」にするよう指示します。出力は必ず録音と照合してください。
- 議事録本文の編集と、構造化された要点・決定事項・アクションは別に保存されます。本文の編集だけでは解析結果欄は変わりません。再生成は本文と解析結果を更新し、完了チェックをリセットします。
- 分割ごとの文字起こし完了時に保存します。送信完了後は画面を閉じても、サーバーの定期処理（約1分ごと）が次の部分の文字起こし、Geminiの待機後の再開、議事録の結果取得を続けます。アプリを開いている間は画面側の確認（処理中は約2.5秒ごと）でも進むため、完成が早くなります。議事録生成はOpenAIのバックグラウンド処理を使います。結果を取得できなかった場合は保存テキストから再生成してください。
- Geminiが文字起こしを完了しなかった部分（`status` が `completed` 以外。出力上限に達した `incomplete` など）は、その部分だけ自動でGPT Transcribeに切り替えます。クラウドでは部分に `transcriptionFallback`（使用モデルとGeminiの状態）を保存し、次の処理でOpenAIへ送信するため、GeminiとOpenAIの呼び出しが同じEdge Functionの実行時間に重なりません。診断コードは `GEMINI_FALLBACK_<状態>` です。会議の詳細ではタイトル下の日付の並びに切り替えた録音を表示し、API使用料にはGPT Transcribeとして記録します。
- Gemini文字起こしは同じ共有ワークスペース内で1部分ずつ処理し、完了後30秒以上間隔を空けます。HTTP 429（一時的な利用制限）では約1分→2分→4分→8分→16分と待機を延ばし、1部分につき最大5回自動再試行します。Googleがより長い待機時間を指定した場合はそちらを優先します。画面に待機理由・残り時間・完了数を表示し、完了済みの部分は再送しません。クラウドに待機時刻を保存し、待機が明けるとサーバーの定期処理が画面を閉じたままでも再開します。
- 日次上限・利用枠ゼロが明示された場合や自動再試行の上限では停止して案内します。Google AI Studioで利用枠・課金設定を確認し、必要なら時間を空けて「再試行」してください。制限に一切かからない保証はありません。1時間以上の音声も合計100 MB・文字起こし10万文字以内で分割処理できますが、録音品質・API利用枠・通信状況によって処理時間や成否が変わります。

## ローカル開発

Node.js 22.18以上。

```sh
npm ci
npm run dev
```

開発画面: http://127.0.0.1:5188 。開発時はローカルモードで、会議・音声を `.data/` に保存します。キーはサーバーのメモリだけに保持し、再起動時は再設定が必要です。環境変数でも設定できます（`.env.example`）。Dropbox配下での開発は `.data` や `.env` が同期される可能性に注意してください。

ローカルで削除した記録は `.data/trash/<ID>/` に移動します。復元時はサーバーを停止し、`meeting.json` を `.data/meetings/<ID>.json`、音声を元の `.data/audio/` へ戻します。

クラウド接続の開発画面:

```sh
VITE_STORAGE_MODE=supabase npx vite --port 5189
```

`npm run build` はGitHub Pages `/multiapp/` 用クラウド版です。`npm start` はローカルAPIサーバー用です（公開環境には不要）。

## 検証

```sh
npm run check
deno check --config supabase/functions/kotonoha-api/deno.json supabase/functions/kotonoha-api/index.ts
deno test --allow-env --config supabase/functions/kotonoha-api/deno.json tests/cloud-api.test.ts
deno test --allow-env --config supabase/functions/kotonoha-api/deno.json tests/cloud-tick.test.ts
deno test --allow-env --config supabase/functions/kotonoha-api/deno.json tests/cloud-bot.test.ts
```

`tests/cloud-bot.test.ts` はGoogle Meet録音Botの流れ（Botの依頼→Webhook→アップロードトークンでの状況報告・取り込み・完了→定期処理で議事録完成）を検証します。トークンが自分の会議以外・ログインが必要なAPIでは使えないこと、完了後・6時間後に無効になること、Webhook失敗時に仮の会議を消すことを確認します。`bash scripts/check-bot-migration.sh` はBot用マイグレーションを使い捨てのローカルPostgreSQLで検証します（本番DBには接続しません）。

`tests/cloud-tick.test.ts` は定期処理（`POST /internal/tick`）を検証します。一覧を取得する画面がなくても分割音声が議事録完成まで進むこと、定期処理と一覧取得が同時に走っても同じ部分を二重に文字起こししないこと、同時AI処理2件の上限、待機時刻前に再開しないこと、合言葉なし・不一致・未設定の要求を拒否することを確認します。

Nodeテストはアップロード・保存・再試行・編集・削除・アクセス制限・APIモデル指定・キー非永続化・定期処理の合言葉照合を確認します。EdgeテストはHTTP通信を模擬し、共通ログイン、OpenAI/Geminiキーの暗号化、GPT/Gemini文字起こし、Astra/Sol/Luna生成、結果取得、音声の取り込みを確認します。実課金リクエストは実行しません。

集計・タグのテストでは、日本時間の期間境界、サンプル除外、現在のキー・モデルの利用、タグ保存後の再読み込み、使用料記録、不完全なAI応答のエラー表示を確認します。一括書き出しは編集本文の保持・ICSの終日予定とエスケープを検証します。

`bash scripts/check-tick-migration.sh` は定期処理のマイグレーションを使い捨てのローカルPostgreSQL（pg_cron入り）で検証します。本番DBには接続しません。

`node scripts/check-features-server.mjs` で独立した検証用サーバーを起動できます（画面 `http://127.0.0.1:5198/`、APIは5197）。一時フォルダーに架空の6会議を用意し、実APIや保存済みキーは使いません。サマリー生成、タグ提案から保存して再読み込み、比較の2〜5件選択・解除を確認し、Ctrl+Cで終了してください。実際のAI出力品質・本番接続・端末ごとの通知は別途確認が必要です。

Geminiの文字起こしには [Interactions APIの文字起こし仕様](https://ai.google.dev/gemini-api/docs/transcribe) を使用します。RESTの `steps[].content` にある `model_output` のテキストを取得し、未完了・応答形式の不一致・空の結果を区別します。応答が読めないだけで「発話なし」とは判定しません。`store: false` を指定し、処理後にはGoogleへ送信した一時音声の削除を要求します。これらは `tests/gemini-transcribe.test.mjs` で検証します。

# MARUGO QR：ファイル公開

- QR管理画面の「ファイルを公開してQRを発行」からPDF・JPG・PNGをアップロードできます。一般公開の確認が必要です。1ファイル20MiB、ワークスペース合計500MiB（未完了アップロードは20MiB予約、公開済みは最低512KiB分計上）です。HTML・SVG・PSDは対象外です。
- 点線の枠へファイルを1つドラッグ＆ドロップするか、クリックして選択できます。選択時に形式・サイズを確認し、選び直すたび公開確認を解除します。ドロップだけではアップロード/公開しません。複数ファイルは拒否し、処理中・未完了の再試行中は選び直しを防ぎます。枠外へファイルを落としてもページ遷移しません。ドロップされたファイルは入力欄のネイティブrequired検証ではなく、同じ選択/公開ガードで検証します。
- 新しい専用 **非公開** Storage bucket `marugo-qr-files` を使い、個人認証と所属店舗を検証したEdge APIだけがアップロード用URLを発行します。アップロードは直接Storageに送るためEdgeに大きなファイルを通しません。公開前にサーバーでサイズ・MIME・先頭シグネチャを検証します。上書きは禁止です。ウイルス検査・PDFの完全な安全性検査ではありません。
- QRアクセスの計測後、`/multiapp/?file=<code>` の一般閲覧画面へ遷移します。閲覧者はログイン不要。ファイル一覧や管理用データは公開しません。閲覧画面はPDF/画像の表示のみで、管理用の名前・ファイル名・容量は表示せず、別画面・ダウンロード・更新ボタンも置きません（管理画面の名前は保持）。ブラウザーのタブ名・読み上げラベルにもファイル名を使いません。PDFはMozilla PDF.js（バージョン固定・worker/フォント等を同一サイト配信）で1ページずつ描画し、複数ページの場合だけページ送りを表示します。ブラウザー標準PDF埋め込みに依存せず、PDF内スクリプト/リンクは実行しません。非対応・期限切れ・読み込み失敗時はブラウザーの再読み込み、解決しない場合は公開元への問い合わせを案内します。閲覧画面の再読み込み自体はQRアクセス数に加算しません。ボタンを消してもブラウザー機能での保存・コピー・スクリーンショットは禁止できず、ファイル名等のAPI応答も非表示にするだけで機密化する機能ではありません。
- 一般閲覧APIは有効・ゴミ箱外のQRに限り、5分有効の署名付き閲覧URLを発行します。停止・ゴミ箱でも発行済みのURLは最大5分有効です。ダウンロード済みのファイルは回収できません。URLを知る人が共有できる一般公開であり、会員限定・機密資料配布用ではありません。
- ゴミ箱はファイル・履歴を保持し、復元は停止中です。完全削除はStorage APIによる本体削除→DB/履歴削除の順です。DBのガードで旧API経由の本体未削除purgeや削除途中の復元を防ぎます。失敗時はゴミ箱で再試行します。Storage SQLで本体の管理行を削除しません。
- 同じ作成IDでアップロード・QR発行を再試行できます。失敗した未公開ファイルは「未公開のアップロードを破棄」で片付けられます。画面を閉じた未完了データは自動削除しません。必要な場合は管理者が所有者と状態を確認して専用Storage API/DB経由で整理します。署名付きアップロードURLは短時間のアップロード権限なので第三者へ共有しないでください。
- セキュリティ確認：既存bucket/認証は変更しない、`qr_files` RLS・匿名/認証済み直接アクセス禁止、RPCはservice-role専用、セッション由来の所有者検証、公開ファイル種別/サイズ制限、一般公開確認、削除時Storage連携を検証してください。
